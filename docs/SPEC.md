# IronMind – Gym AI App Spec for Claude Code

Oct 20, 2026 · @Mohamed

## 1. نظرة عامة والتقنيات

أبلكيشن Android شخصي (مستخدم واحد، بدون تسجيل حسابات) يغطي كل حاجة في الجيم: التمارين، التغذية، النوم، الجسم، ومدرب ذكي مبني على Claude API. الاسم المقترح: **IronMind** (بدائل: RepCoach، عضلة، Forge).

**ملاحظة لـ Claude Code:** ابنِ الأبلكيشن كله في مرحلة واحدة (طلب صريح من المستخدم)، لكن اشتغل بترتيب منطقي واعمل build وتشغيل بعد كل جزء عشان الأخطاء متتراكمش.

| البند | القرار |
| --- | --- |
| المنصة | Android (مع إمكانية iOS مستقبلاً) |
| الإطار | Flutter (أحدث نسخة stable) + Dart |
| إدارة الحالة | Riverpod |
| قاعدة البيانات | محلية فقط — Drift (SQLite) أو Isar |
| الـ AI | Claude API مباشرةً من الموبايل (المفتاح يتدخل من الإعدادات) |
| اللغة | عربي + إنجليزي مع زرار تبديل، RTL كامل للعربي (flutter\_localizations + ARB files) |
| الوحدات | كيلوجرام وسنتيمتر |
| الأوفلاين | كل التسجيل يشتغل بدون نت، طلبات الـ AI تدخل طابور وتتبعت لما النت يرجع |
| التصميم | Dark mode، اللون الرئيسي أخضر نيون (#39FF14 تقريبًا) على أسود |

الهيكل: Feature-first folders (onboarding, workout, exercises, nutrition, tracking, coach, progress, settings) + طبقة data منفصلة (repositories) + طبقة ai\_service واحدة هي اللي بتكلم Claude.

## 2. الأونبوردنج (أول فتح للأبلكيشن)

أول مرة يفتح الأبلكيشن يعرض استبيان شامل، سؤال في كل شاشة باختيارات (زي الكروت) + شريط تقدم، وزرار رجوع. المستخدم هو اللي بيختار والـ AI يبني الخطة على إجاباته. كل الإجابات تتحفظ في Profile وتتعدل لاحقًا من الإعدادات (تعديلها يعرض إعادة توليد الخطة).

الأسئلة بالترتيب:

1. اللغة (عربي / English)
2. النوع، السن، الطول، الوزن الحالي
3. نسبة الدهون (رقم أو اختيار شكل جسم تقريبي أو "مش عارف")
4. مقاسات الجسم الأولية (وسط، صدر، ذراع، فخذ، رقبة، أرداف) — اختيارية
5. الهدف: تضخيم / تنشيف / ريكومب / قوة / لياقة عامة + الوزن المستهدف والمدة
6. المستوى: مبتدئ / متوسط / متقدم + مدة التمرين السابقة
7. أيام التمرين في الأسبوع (2–7) + اختيار الأيام نفسها (سبت، حد...)
8. مدة التمرينة (30 / 45 / 60 / 75 / 90 دقيقة)
9. أسلوب التمرين المفضل: مجموعة عضلات في اليوم / عضلة واحدة (Bro Split) / Full Body / PPL / Upper-Lower / "سيب الـ AI يختار"
10. العضلات اللي عايز تركز عليها (اختيار متعدد)
11. مكان التمرين: جيم كامل / جيم محدود / بيت
12. الإصابات والمشاكل الصحية (كتف، ركبة، ظهر سفلي، ضغط، سكر... + خانة كتابة)
13. طبيعة الشغل (مكتبي / متحرك / مجهود بدني) ومواعيده
14. مواعيد النوم والصحيان المعتادة
15. معاد التمرين المعتاد (صبح / بعد الشغل / ليل)
16. الكارديو: نوعه وكام مرة أسبوعيًا
17. عدد الوجبات في اليوم ومواعيدها
18. أكلات بتحبها / مبتحبهاش / حساسية
19. ميزانية الأكل الشهرية بالجنيه (منخفضة / متوسطة / مفتوحة أو رقم)
20. المكملات الحالية (واي، كرياتين، فيتامينات... + الجرعات)
21. هدف الميه اليومي (الـ AI يقترح رقم حسب الوزن)
22. ربط Health Connect (الخاتم) — أو تخطي
23. مفتاح Claude API — أو تخطي ويتحط لاحقًا
24. شاشة ملخص لكل الإجابات ← زرار "ابني خطتي"

الـ AI يحسب من الإجابات: BMR/TDEE، هدف السعرات، الماكروز، هدف الميه، ويبني خطة التمرين والأكل.

## 3. خطة التمرين والتسجيل أثناء التمرين

الـ AI يولّد الخطة، يعرضها للمستخدم، والمستخدم يعدل (يشيل/يضيف/يبدل/يغير ترتيب بالسحب) قبل الاعتماد.

**الخطة:**

- أسبوعية: كل يوم ليه اسم (مثلاً Push A) وقائمة تمارين: عدد الستات، نطاق العدات، الوزن المقترح، RPE مستهدف، زمن الراحة.
- إحماء في الأول وإطالة في الآخر، مناسبين لعضلات اليوم.
- الـ AI يراعي الإصابات والمدة والمكان.
- Deload ذكي: الـ AI يقترح أسبوع تخفيف كل 4–6 أسابيع حسب الأداء والاستشفاء.
- لو المستخدم فوّت يوم: يتسجل "غياب" بس والجدول ميتغيرش.

**شاشة التمرينة الحية:**

- زرار "ابدأ تمرينة النهاردة" + عداد وقت التمرينة كلها. الشاشة متطفيش أثناء التمرين (wakelock).
- لكل ست: الوزن، العدات، RPE (1–10)، ونوع الست (عادي / إحمائي / Drop set / لحد الفشل).
- جنب كل ست يظهر أرقام المرة اللي فاتت + اقتراح الـ AI للمرة دي (Progressive Overload أوتوماتيكي، مثلاً "جرب 82.5 بدل 80"). الاقتراح ده يتحسب محليًا بقواعد (double progression) عشان يشتغل أوفلاين، والـ AI يراجعه في الملخص.
- إدخال سريع: أزرار +/− للوزن والعدات، وزرار نسخ الست اللي فات.
- إدخال بالصوت: المستخدم يقول "80 كيلو 10 عدات" (عربي مصري أو إنجليزي) ← speech\_to\_text ← parser محلي بالـ regex للأرقام، ولو فشل يبعت النص لـ Claude (Haiku) يرجّع JSON. يعرض النتيجة للتأكيد قبل الحفظ.
- تايمر الراحة: يتشغل يدويًا بزرار (مش أوتوماتيك)، مدته الافتراضية من الخطة وتتعدل، ينبه باهتزاز وصوت حتى لو الأبلكيشن في الخلفية.
- زرار "بديل" لكل تمرين: يقترح 3 تمارين لنفس العضلة والحركة (من المكتبة محليًا أولاً، ومن الـ AI لو في نت)، مع الاختيار: للتمرينة دي بس / دايمًا.
- كارديو: النوع + المدة + السرعة/الميل أو المستوى + حساب تقريبي للسعرات (MET).
- نوتة نصية لكل تمرين وللتمرينة (مثلاً "الكتف بيوجع").
- كشف PR أوتوماتيكي (أعلى وزن، أعلى عدات لنفس الوزن، أعلى 1RM محسوب بمعادلة Epley) ← احتفال بأنيميشن (confetti) + اهتزاز.
- في النهاية: ملخص (الوقت، الحجم الكلي، الـ PRs) + تقييم المدرب الذكي (القسم 7).

## 4. مكتبة التمارين

مكتبة محلية جاهزة مع الأبلكيشن (seed data) بحد أدنى \~300 تمرين، مأخوذة من مصدر مفتوح زي free-exercise-db (رخصته تسمح) أو ExerciseDB. يا Claude Code: اتأكد من رخصة المصدر اللي هتستخدمه واختار اللي ينفع يتخزن محليًا.

كل تمرين فيه:

- الاسم بالعربي والإنجليزي
- صورة متحركة (GIF) أو صور خطوات — تتحمل وتتخزن (cache) عشان تظهر أوفلاين
- شرح مكتوب بالخطوات + الأخطاء الشائعة
- رسم جسم (أمامي وخلفي، SVG) بيلوّن العضلات الأساسية بالأخضر الغامق والثانوية بالفاتح
- الأداة (بار، دمبل، كابل، ماكينة، وزن جسم...)، نوع الحركة (دفع/سحب/رجل...)، مركب أو عزل
- سجل المستخدم في التمرين ده: آخر أداء، الـ PR، رسم تطور

البحث والفلترة: بالاسم، العضلة، الأداة. مفضلة (نجمة).

**إضافة تمرين جديد بالـ AI:** المستخدم يوصف التمرين بكلامه (كتابة أو صوت، وممكن صورة للجهاز)، وClaude يرجّع JSON فيه الاسم، العضلات، الأداة، الشرح، الأخطاء. يتعرض للمراجعة وبعدين يتحفظ كتمرين custom. لو فيه تمرين مشابه موجود، يقترحه الأول بدل التكرار.

## 5. التغذية

الـ AI يحدد أرقام يومية (سعرات، بروتين، كارب، دهون) **وكمان** خطة وجبات كاملة بالجرامات، والمستخدم يقدر يبدّل أي وجبة أو ياكل برا الخطة ويسجل بس.

**خطة الأكل:**

- أكل مصري ومتاح في مصر (فول، بيض، فراخ، تونة، أرز، عيش بلدي، زبادي، جبنة قريش، كشري، لحمة مفرومة...).
- يراعي الميزانية والأكلات اللي بتحبها ومبتحبهاش وعدد الوجبات ومواعيدها.
- أيام التمرين ممكن يبقى فيها كارب أعلى من أيام الراحة.
- زرار "بدّل الوجبة" يدي 2–3 بدائل بنفس الماكروز تقريبًا.
- قائمة مشتريات أسبوعية تتولد من الخطة (ميزة إضافية مقترحة).

**تسجيل الأكل:**

- **بالصورة:** المستخدم يصور الطبق ← الصورة تتضغط (أقصى ضلع \~1024px) ← تتبعت لـ Claude (vision) ← يرجّع JSON بالمكونات والكميات التقديرية والسعرات والماكروز + درجة ثقة. المستخدم يعدل الكميات قبل الحفظ.
- **بالكتابة أو الصوت:** مثلاً "طبق كشري وسط وبيضتين" ← Claude يحوله لنفس الـ JSON.
- الأكلات اللي اتسجلت قبل كده تتحفظ في "أكلاتي" للتسجيل السريع بضغطة من غير AI (توفير فلوس وشغال أوفلاين).
- المكملات (واي مثلاً) بتدخل في حساب البروتين والسعرات.

الشاشة اليومية: حلقة تقدم للسعرات + أشرطة للماكروز + الوجبات (مخطط مقابل اللي اتاكل فعلاً) + المتبقي لليوم.

## 6. التتبع اليومي والجسم والخاتم الذكي

- **الميه:** زرار ضغطة واحدة (كوباية 250 مل أو زجاجة بحجم يحدده المستخدم) + هدف يومي.
- **المكملات:** تسجيل فقط (من غير اقتراحات)، قائمة بالمكملات اللي بياخدها وعلامة ✓ يومية.
- **النوم:** المدة + المراحل من الخاتم، ولو مش متاح إدخال يدوي (ساعات + جودة من 1–5).
- **وزن الجسم:** يومي، ويتعرض معاه متوسط متحرك 7 أيام عشان التذبذب اليومي ميضايقش.
- **المقاسات:** أسبوعية (وسط، صدر، ذراع، فخذ، رقبة، أرداف) + نسبة دهون اختيارية.
- **صور التقدم:** أمامي / جانبي / خلفي، تتحفظ جوه مجلد الأبلكيشن الخاص (مش في الجاليري)، مع شاشة مقارنة جنب بعض (اختيار تاريخين) وسلايدر قبل/بعد. محمية بالبصمة.

**الخاتم الذكي (Cardoo) عن طريق Health Connect:**

- استخدم باكدج `health` لقراءة: النوم ومراحله، نبض القلب والنبض وقت الراحة، HRV، الخطوات، السعرات المحروقة.
- **سؤال مفتوح:** مش مؤكد إن تطبيق خاتم Cardoo بيكتب بياناته في Health Connect. لازم شاشة في الإعدادات تعرض "آخر بيانات اتسحبت ومصدرها" عشان المستخدم يتأكد. لو مفيش بيانات، الأبلكيشن يرجع للإدخال اليدوي من غير ما يبوظ حاجة.
- **درجة استشفاء يومية (0–100):** محسوبة من النوم + HRV + نبض الراحة مقارنة بمتوسط المستخدم. لو واطية، المدرب يقترح تخفيف تمرينة اليوم (أوزان أقل أو ستات أقل) والمستخدم يوافق أو يرفض.
- المزامنة تحصل عند فتح الأبلكيشن + background sync بـ workmanager كل كام ساعة.

## 7. المدرب الذكي وربط Claude API

**الشخصية:** مدرب صارم ومباشر، بيتكلم بالمصري (أو إنجليزي حسب لغة الأبلكيشن)، بيزقّ لو المستخدم قصّر بس من غير إهانة، ومبيبالغش في المدح. يبني كلامه على الأرقام الحقيقية من السجل. في أي ألم حاد أو عرض صحي مقلق يوقف الصرامة وينصح بدكتور.

**الشات:** شات كامل عارف بيانات المستخدم. مع كل رسالة يتبعت ملخص context مضغوط (البروفايل، الخطة الحالية، آخر 7 أيام تمرين وأكل ووزن ونوم، الـ PRs، الذاكرة) مش الداتا كلها. استخدم prompt caching للـ system prompt والبروفايل. الردود streaming.

**الذاكرة:** بعد كل محادثة، الـ AI يستخلص الملاحظات المهمة ("الكتف الشمال بيوجع في الـ Overhead Press") ويحفظها في جدول coach\_memory. المستخدم يقدر يشوفها ويمسحها من الإعدادات.

**شات ينفذ أوامر (tool use):** الـ AI عنده tools زي `propose_plan_change`، `swap_exercise`، `log_meal`، `log_set`، `adjust_macros`. أي تغيير في الخطة يتعرض ككارت "اقتراح" بزرارين موافق/رفض — مفيش تغيير أوتوماتيكي من غير موافقة.

**المبادرات (الـ AI يكلم المستخدم من نفسه):**

| المبادرة | التوقيت | المحتوى |
| --- | --- | --- |
| رسالة الصبح | بعد معاد الصحيان | خطة اليوم + درجة الاستشفاء + أي تعديل مقترح |
| ملخص التمرينة | بعد إنهاء أي تمرينة | إيه اتحسن، إيه ضعيف، هدف المرة الجاية |
| تنبيه Plateau | لما تمرين ميتحسنش 3 جلسات ورا بعض | السبب المحتمل + حل (تغيير عدات، تمرين بديل، deload) |
| التقرير الأسبوعي | آخر الأسبوع | تمرين + أكل + وزن + نوم + التزام + اقتراحات للخطة |

كشف الـ Plateau محلي بقاعدة (من غير AI)، ولما يكتشف حاجة يطلب الشرح من Claude. المبادرات بتظهر كإشعار + رسالة في الشات.

**الموديلات (تقسيم ذكي):** أسماء الموديلات تبقى في ملف config وتتغير من الإعدادات. يا Claude Code: راجع docs.claude.com على أحدث أسماء وأسعار.

| المهمة | الموديل الافتراضي |
| --- | --- |
| تحويل صوت/نص لـ JSON، بدائل التمارين، استخلاص الذاكرة | claude-haiku-5-5 |
| الشات، ملخص التمرينة، تحليل صور الأكل، رسالة الصبح | claude-sonnet-5-5 |
| بناء الخطة الأولى، خطة الأكل، التقرير الأسبوعي | claude-opus-5-5 |

**المخرجات المنظمة:** أي طلب بيرجع داتا (خطة، وجبة، ست) يستخدم tool use / JSON schema ويتعمل له validation قبل الحفظ، مع إعادة محاولة مرة واحدة لو فشل.

**المصاريف:** عداد في الإعدادات يعرض التوكنز والتكلفة التقديرية بالدولار (النهاردة / الشهر / لكل ميزة)، من غير حد أقصى.

**الأوفلاين:** طلبات الـ AI اللي مش عاجلة (ملخصات، تحليل صور أكل) تدخل طابور وتتبعت لما النت يرجع. الشات يقول بوضوح "مفيش نت".

## 8. التقدم والإشعارات والتصميم

**الرسوم البيانية (fl\_chart):**

- تطور وزن كل تمرين + 1RM المتوقع عبر الوقت
- حجم التمرين الأسبوعي لكل عضلة (وزن × عدات × ستات، وعدد الستات الفعّالة)
- وزن الجسم (يومي + المتوسط المتحرك) والمقاسات
- السعرات والماكروز مقارنة بالهدف
- النوم ودرجة الاستشفاء
- فلتر فترة: أسبوع / شهر / 3 شهور / سنة / الكل

**الالتزام:** كاليندر شهري ملون (أخضر = تمرينة كاملة، أصفر = جزئية، أحمر = غياب، رمادي = راحة). ضغطة على اليوم تفتح تفاصيله. صفحة الـ PRs بكل الأرقام القياسية وتواريخها.

**تقارير PDF:** تصدير أسبوعي/شهري (الرسوم + الجداول + ملخص المدرب) ومشاركته من الـ share sheet. لازم يدعم العربي RTL (خط عربي مدمج زي Cairo).

**الإشعارات (flutter\_local\_notifications)، كل واحد يتقفل ويتعدل ميعاده لوحده:**

- ميعاد التمرين (أيام التمرين بس)
- مواعيد الوجبات
- الميه (كل X ساعة في فترة الصحيان) والمكملات
- تسجيل الوزن الصبح
- مبادرات المدرب (القسم 7)

**التصميم:**

- Dark mode فقط، خلفية قريبة من #0A0A0A، كروت #161616، اللون الرئيسي أخضر نيون للأزرار والحلقات والـ PRs.
- خط عربي واضح (Cairo أو IBM Plex Sans Arabic) وإنجليزي (Inter).
- أزرار كبيرة في شاشة التمرين (الإيد ممكن تبقى عرقانة)، أقل عدد ضغطات لتسجيل ست.
- Haptics عند حفظ الست والـ PR.

**التنقل — 5 تابات تحت:**

1. **اليوم:** رسالة المدرب، درجة الاستشفاء، تمرينة النهاردة (زرار ابدأ)، حلقات السعرات والميه، المكملات، الوزن
2. **التمرين:** الخطة الأسبوعية، السجل، مكتبة التمارين
3. **الأكل:** خطة الوجبات، التسجيل (كاميرا / صوت / كتابة / أكلاتي)، قائمة المشتريات
4. **المدرب:** الشات والتقارير والاقتراحات المعلقة
5. **التقدم:** الرسوم، الكاليندر، الـ PRs، صور التقدم، المقاسات

الإعدادات من أيقونة فوق: البروفايل، اللغة، الـ API key، الموديلات، عداد المصاريف، الإشعارات، Health Connect، ذاكرة المدرب، النسخ الاحتياطي، قفل البصمة.

**ويدجت الشاشة الرئيسية (home\_widget):** تمرينة النهاردة، السعرات المتبقية، الميه مع زرار "+ كوباية" مباشرة.

## 9. البيانات والأمان وتعليمات البناء

**الأمان:**

- مفتاح Claude API يتدخل من الإعدادات ويتحفظ بـ flutter\_secure\_storage. ممنوع يتكتب في الكود أو يترفع على git. زرار "اختبر المفتاح".
- قفل الأبلكيشن بالبصمة (local\_auth) عند الفتح وبعد مدة في الخلفية، قابل للإيقاف.
- صور التقدم في مجلد الأبلكيشن الخاص، وما تتبعتش للـ API غير بطلب صريح.

**النسخ الاحتياطي:** تصدير ملف واحد (zip فيه القاعدة + الصور) من الإعدادات ومشاركته لـ Drive أو أي مكان، واستيراده على موبايل جديد. تذكير كل أسبوعين لو ماتعملش backup. مفتاح الـ API مش جزء من الـ backup.

**تعليمات لـ Claude Code:**

1. ابدأ بـ `flutter create`، هيكل الفولدرات، الثيم، الترجمة، والقاعدة.
2. ابنِ كل الميزات في الملف ده (المستخدم عايزها كلها)، بالترتيب: الأونبوردنج ← مكتبة التمارين ← الخطة والتسجيل ← التغذية ← التتبع وHealth Connect ← المدرب ← التقدم والتقارير ← الإشعارات والويدجت ← النسخ الاحتياطي والقفل.
3. بعد كل جزء: `flutter analyze` + تشغيل + unit tests للحسابات (TDEE، 1RM، progressive overload، plateau، recovery score، voice parser).
4. ابني الـ AI service بحيث ينفع تشغيل الأبلكيشن كله بدون API key (مع رسالة واضحة مكان ميزات الـ AI).
5. الناتج النهائي: APK موقّع (release) المستخدم ينزله على موبايله مباشرة، + README بالعربي بخطوات التثبيت وإضافة المفتاح.
6. لو في أي قرار مش محسوم هنا، اختار الأبسط والأكثر شيوعًا واكتبه في ملف DECISIONS.md.
